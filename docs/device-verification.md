# 设备验证

1. 在连接设置中填写后端地址，点击「设备验证」。
2. 在后端 TUI 按 `d` 打开设备验证，选择对应申请，核对双方完整的 `XXXXX-XXXXX` 验证码。
3. 按 `a` 批准，或按 `r` 拒绝。设备名称由客户端自报，核对时以验证码为准。
4. 批准后客户端保存此后端的访问令牌。导入后端要求的加密公钥后，点击「连接」；后续连接无需再次粘贴令牌。

申请有效期为 5 分钟，可在客户端取消。切换后端或修改地址会取消当前申请；过期、拒绝、取消以及领取过的请求不能再次领取令牌。

设备验证只更新访问令牌。启用 X25519 或 ML-KEM-768 时，仍须用二维码或复制粘贴导入后端的传输加密公钥。可以先导入公钥，也可以先验证设备；同一后端的无令牌二维码不会清空已保存的令牌，不同后端不会继承旧令牌。

后端配置 X25519 或 ML-KEM-768 后，会强制要求对应的传输加密；客户端未选择该协议、未导入公钥或公钥错误时，连接设置会提示尚未完成加密密钥传输验证。客户端成功完成加密往返验证后才显示已连接。后端设置为 None 时，允许不加密连接，也允许客户端选择加密。TUI 保存加密设置后会重启正在运行的 daemon，使新要求生效。

此功能需更新后端和客户端。旧后端仍可用原有手动令牌方式连接；更新后端后，重启 daemon 和 TUI 才会启用申请和审批入口。

## 实现边界

批准入口只读取和写入后端本机的私有控制目录，没有公网批准 API。网络上的申请、查询和取消请求有大小、数量及频率限制。

客户端为单次申请生成临时 X25519 密钥，双方从同一握手内容计算验证码。后端批准后使用 HKDF-SHA256 和 XChaCha20-Poly1305 加密交付现有访问令牌；只有发起申请的客户端能够解密。临时密钥不替代、不导入后端的长期传输加密公钥。

批准沿用后端现有访问令牌和权限模型，不创建独立的设备账户。重置后端令牌后，已保存的旧令牌失效，需要重新验证或更新令牌。令牌领取响应丢失时，需要重新申请。

## 历史记录加密

后端开启 `e2e` 后，会话历史以密文保存，只有登记过的设备与恢复密钥能读取（规格见后端 `docs/history-encryption.md`）。

- 客户端连接后端时为该后端生成一把历史密钥（X-Wing 种子）并通过 `history.recipient.register` 登记公钥。桌面端用系统钥匙串（Electron safeStorage）加密种子；没有可用密钥服务的 Linux 桌面会拒绝保存而不是明文落盘。
- 「设置 → 历史记录加密」显示模式与可读取历史的密钥（此设备、其他设备、恢复密钥），可吊销其他密钥、开启或关闭加密。首次开启会展示 24 个 BIP39 英文单词与二维码作为恢复密钥，确认已保存后才上传其公钥；跳过需要二次确认。
- 新设备只能读取登记之后写入的历史。点「请求访问旧历史」后，在已授权设备的同一面板点「授权」，客户端会逐批取回自己的封装、解开后为新设备重新封装并上传；中断后可继续。
- 导入恢复密钥（24 个单词或二维码文字）等同一次自授权，之后此设备即可读取恢复密钥覆盖的历史；恢复密钥本身不会保存。
- 只有 `/v2/version` 报告 `historyEncryption: 1` 的后端会显示此功能；授权请求与授权结果都不推送：重连与打开设置面板时会重新读取；本机有待处理的授权请求时每 15 秒查询一次，授权完成后无需刷新即解锁已显示的历史。此设备的密钥被吊销后无法再次登记，客户端会生成新密钥重新登记，旧历史需重新授权或导入恢复密钥。
- 无法解密的历史显示为「此设备尚未获授权查看这段历史」，不影响其余内容；加密模式下 `/retry` 会附带本机解密出的原始消息。
