# Git 操作菜单

Desktop 与 Web 使用相同菜单，并在工作区对应的后端执行固定 Git 操作。

- 直接执行：初始化（不创建提交）、普通推送、分支查看/创建/切换、工作树查看/创建/打开/移除、创建 PR。
- Agent：提交、提交并推送、Handoff，以及 PR 查看、解释、修复、合并与管理。消息发送到当前对话，运行中的对话使用现有候选队列。
- 固定操作失败只显示错误。用户点击“交给 Agent 处理”后，才发送包含工作区、实际参数和错误的诊断请求。网络中断或超时可能已执行，刷新核对之前禁止重复写入。

创建分支不切换当前分支；切换要求工作区干净。创建工作树需要新分支和后端允许根目录内不存在的绝对路径。打开工作树会选择/创建对应工作区和对话，不迁移原对话的 native session；任务上下文交接使用 Handoff。移除需要确认具体目录，且只允许干净、未锁定、非当前、非主工作树；保留分支，含忽略文件的目录也不能直接移除。

后端新增 `GET /v2/git/workspace?workspacePath=...` 与 `POST /v2/git/operation`，沿用认证与工作区信任检查。请求使用结构化操作参数，不拼接 shell，不自动重试。旧后端不支持这些端点时显示错误，可由用户选择交给 Agent 诊断。

验证包含真实 Git 临时仓库测试、认证/信任/路径边界测试、前端直接执行与手动接管交互测试、双端类型检查与构建，以及 390px 窄屏表单检查。

## 对话顶部状态

Agent 标签旁显示当前所属仓库的分支、主/关联工作树、变更文件数与绿色新增/红色删除行数；悬停显示仓库路径，点击打开 Git 菜单。分离 HEAD 明确标注。未初始化、断线和读取失败都有独立状态，不沿用其他工作区的数据。

`GET /v2/git/status?workspacePath=...` 只读取当前所属仓库，允许工作区是仓库子目录，不扫描子仓库或其他工作树。文件数包含暂存、未暂存和未跟踪项；行数统计相对 HEAD 的净更改及未跟踪文本。二进制不计行数，超过有界统计限制时显示省略标记和部分结果提示。

前台空闲每 30 秒刷新，Agent 运行时每 5 秒刷新；切换对话、连接恢复、任务状态变化、Git 菜单开关和窗口重新获得焦点时刷新。隐藏页面暂停轮询，旧请求会在切换时取消，失败不会发送 Agent 消息。

顶栏按中间区域的实际可用宽度决定呈现方式。空间不足时，标题、Agent、工作区和 Git 信息统一收进“三个点”菜单；左右面板按钮及右侧操作保持单行且不收缩。窄屏右侧工作台使用抽屉显示。

## PR 工作流

“PR 与代码更改”提供直接创建表单，填写 GitHub 仓库（`owner/repository` 或 `host/owner/repository`）、目标分支、标题、描述和草稿状态。后端通过已登录的 `gh` 创建；要求当前分支存在 upstream，目标仓库与 upstream 远端一致，且 GitHub 上分支提交与本地 HEAD 一致。不自动提交或推送；需要时先使用现有提交/推送入口。同一分支与目标分支已有开放 PR 时返回已有链接。跨 fork 的 PR 暂不支持直接创建。

其余 PR 操作均交给当前对话 Agent：

- 查看 PR、解释代码更改。
- 处理审查评论、修复失败检查、解决合并冲突、处理全部问题。
- 合并、启用自动合并、取消自动合并。
- 管理标题/描述/标签/审查人、转草稿、标记可供审查、关闭、重新打开。

Agent 先核对当前分支对应的 PR；候选不唯一时询问具体目标。修复保留无关更改并验证，合并遵守仓库保护规则并核对最新提交；不默认删除分支或工作树。菜单不展示未经读取的 PR 状态或问题计数，实际状态由 Agent 查询后在对话中报告。管理入口没有具体修改要求时先给出选项。

创建结果未知时不自动重试，普通 Git 状态刷新不会解除 PR 创建锁定，可点击“交给 Agent 处理”核对实际 PR。后端需要更新到支持 `create-pr` 的版本；旧后端或缺少 GitHub CLI/认证时显示具体错误。
