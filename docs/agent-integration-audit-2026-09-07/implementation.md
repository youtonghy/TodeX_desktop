# A、B、C 阶段实施记录

实施日期：2026-09-08。对应审查报告中的 A（现有承诺修复）、B（连接与配置基础）、C（优先能力）。原审查报告描述实施前状态；本文件记录本次交付。

## 已交付

- Codex、Grok Build、Pi 使用按会话复用的进程与单一 stdout 消费者。运行中命令、权限回答和通知通过同一连接处理；空闲进程有数量上限和回收期限，删除会话及后端关闭时释放进程。
- v2 新增 `conversation.control`：要求 owner、workspace trust、活动回合 ID 和请求 ID。控制事件持久化为 requested/completed/rejected/unknown；丢回执不重发，同 ID 不同输入拒绝。Prompt 同样以输入指纹去重，已消费的原生队列 ID 不会再次启动任务。
- 桌面和网页提供“本轮已确认配置”“下轮选择”“应用到本轮后续步骤”和文字纠偏。Provider 回执或读取确认后才更新有效配置；已发出的模型请求不会因选择器改变而重新执行。
- Codex/Pi 使用原生文字队列；Grok 及带附件/技能的追加内容使用本地候选队列。本地候选持久化，重载后暂停，失败/取消不自动推进。终态先于提交回执时仍正确推进下一项。
- Grok/Pi 接入原生会话分支，Pi 接入原生压缩。沿用现有 Fork 与压缩入口及后端权限边界。
- Codex 修复 Plan 参数、模型分页、commentary/final 流、推理分块、未知 item 保留及 MCP elicitation。共享投影显示进展，且不将其合并为最终答案。
- Grok 修复 new/load 审批一致性、扩展方法分派、最终 metadata、用量汇总和动态命令读取。最终回合用量替换此前的请求统计，避免重复累加。优雅取消保留已收到的终态 metadata。
- Pi 修复 pre-ACK 通知、错误终态、纯扩展命令、扩展 UI 超时、原生身份及严格 session 恢复。非致命扩展 hook 错误不会覆盖已成功的模型终态。
- 审批界面支持 MCP 基础标量表单、枚举和 URL 完成确认，Codex user input，以及 Pi confirm/select/input/editor。后端校验回答结构与待处理请求一致；不支持的嵌套表单明确提示，不能空回答伪装成功。

## 能力边界

- Codex 新控制基于安装二进制只读导出的 experimental JSON schema 探测，按方法和参数字段确认；导出失败或接口缺失时禁用，并返回 `controlProbe` 诊断。结果在当前后端进程内缓存，升级 CLI 后需重启后端再探测。
- Grok/Pi 使用源码核对并以协议 fixture 验证的原生接口。安装版若拒绝某接口，显示明确错误，不悄悄改为普通 prompt。没有执行需要付费模型调用的真实会话验收。
- 纠偏与原生排队当前仅支持文字；附件和 Skill 进入本地候选队列。Pi 没有安全的原生单项删除接口，因此提供明确标注的“清空待处理输入（含纠偏）”，不以清空重建模拟单项删除。
- 原生进程在取消、错误或不确定结果后可能被释放；遗留队列显示暂停/待核对，不能保证仍会执行。不会自动把这些内容重新提交。
- 本次不包含 D/E 阶段：原生历史树/rewind、MCP 热更新、富产物工作台、Codex 搜索/后台终端及语音。
